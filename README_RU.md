# VEYRA — язык программирования для Linux

**VEYRA 0.2.0** — экспериментальный язык с расширением `.vey`, интерпретатор написан на C++20. Цель — понятный синтаксис для обучения программированию и создания небольших read-only Linux security-проверок.

Это рабочий прототип языка, но не сертифицированный security-инструмент и не песочница.

## Возможности 0.2.0

- переменные `let` и неизменяемые значения `const`;
- числа, строки, `true`, `false`, `none`, арифметика, сравнения и логические операторы;
- `if/else`, `while`, C-подобный `for`, `break`, `continue`;
- пользовательские функции `fn` и `return`;
- локальная область видимости блоков;
- стандартные функции `text.*` и `math.*`;
- Linux-информация и read-only функции проверки метаданных файлов;
- режим `--check` для синтаксической проверки без исполнения;
- тесты для бесконечных циклов, `const`, областей видимости и опасных целей хеширования.

## Сборка на Arch Linux / Veyra Linux

```bash
sudo pacman -S --needed base-devel openssl
make clean
make
make test
```

Запустить примеры:

```bash
./veyra examples/hello.vey
./veyra examples/basics.vey
./veyra examples/advanced.vey
./veyra examples/factorial.vey
./veyra examples/security_audit.vey
```

Установка команды в `/usr/local/bin`:

```bash
sudo make install
veyra --version
```

## Команды CLI

```bash
veyra file.vey              # исполнить файл
veyra --check file.vey      # проверить синтаксис без исполнения
veyra --builtins            # вывести список встроенных функций
veyra --version             # версия
veyra --help                # справка
```

`--check` проверяет лексический и синтаксический разбор, но пока не выполняет полноценную статическую проверку типов и неизвестных имён.

## Пример языка

```vey
const limit = 8;
let total = 0;

for (let i = 0; i < limit; i = i + 1) {
    if (i == 2) {
        continue;
    }
    if (i == 6) {
        break;
    }
    total = total + i;
}

fn greet(name) {
    return "Привет, " + text.trim(name);
}

print greet(" Abduali ");
print "Сумма = " + total;
print "Корень = " + math.sqrt(81);
```

Поддерживаются комментарии `#` и `//`. После простых инструкций точка с запятой необязательна; в заголовке `for` разделители `;` обязательны.

## Стандартные функции

### Строки

| Функция | Поведение |
|---|---|
| `text.len(s)` | длина строки в байтах (не Unicode-кодовых точках) |
| `text.lower(s)` / `text.upper(s)` | преобразование ASCII-регистра |
| `text.trim(s)` | удаление пробельных символов по краям |
| `text.contains(s, part)` | входит ли подстрока |
| `text.starts_with(s, prefix)` | начинается ли строка с префикса |
| `text.ends_with(s, suffix)` | заканчивается ли строка суффиксом |

### Математика

`math.abs(n)`, `math.floor(n)`, `math.ceil(n)`, `math.round(n)`, `math.sqrt(n)`, `math.min(a, b)`, `math.max(a, b)`, `math.pow(a, b)`.

Некорректные результаты, например квадратный корень из отрицательного числа или переполнение до бесконечности, приводят к ошибке.

### Информация о Linux

| Функция | Поведение |
|---|---|
| `linux.os()` | `Linux` |
| `linux.kernel()` | версия ядра |
| `linux.arch()` | архитектура |
| `linux.hostname()` | имя узла |
| `linux.pid()` | PID процесса VEYRA |
| `linux.page_size()` | размер страницы памяти, сообщённый ядром |
| `system.cwd()` | текущий рабочий каталог |

### Проверки безопасности

| Функция | Поведение |
|---|---|
| `security.is_root()` / `security.uid()` | эффективный root / реальный UID |
| `security.exists(path)` | проверка существования через `access` |
| `security.readable(path)` / `security.writable(path)` / `security.executable(path)` | проверка доступности процессу |
| `security.mode(path)` | биты режима в восьмеричном виде, метаданные через `lstat` |
| `security.audit(path)` | краткая сводка типа, режима, владельца и нескольких рискованных битов |
| `security.sha256(path)` | SHA-256 обычного файла не больше 256 MiB |
| `security.is_file(path)` / `security.is_directory(path)` / `security.is_symlink(path)` | тип файловой системы через `lstat` |
| `security.size(path)` / `security.owner_uid(path)` | размер и UID владельца |
| `security.world_writable(path)` / `security.setuid(path)` | проверка соответствующих битов режима |

`security.sha256` открывает файл с `O_NOFOLLOW`, проверяет открытый файловый дескриптор через `fstat` и читает ограниченный объём данных. Это снижает риск следования символической ссылке и хеширования устройств вроде `/dev/zero`. Как и любые проверки файловой системы, эти функции не устраняют все возможные гонки состояния и не заменяют защищённую среду исполнения.

## Ограничения безопасности

- Никакого встроенного запуска shell-команд или сетевых запросов.
- Нет встроенной произвольной записи файлов.
- Максимальный размер исходного файла: 4 MiB.
- Максимум 250 000 токенов и глубина синтаксиса 256.
- Общий лимит итераций циклов: 1 000 000.
- Общий лимит исполнения: 5 000 000 инструкций и 20 000 000 вычислений выражений; вывод ограничен 16 MiB, строка — 4 MiB.
- Максимальная глубина вызовов функций: 256.
- Лимит SHA-256: 256 MiB на обычный файл.
- SHA-256 реализован через OpenSSL EVP, не через самописную криптографию.
- Сборка исходника runtime содержит compile-time проверку `__linux__`.

**Важно:** VEYRA — не sandbox. Код `.vey` выполняется с правами пользователя и может читать метаданные и хешировать файлы, к которым имеет доступ. Не запускайте недоверенные программы; не запускайте VEYRA с `sudo` без необходимости. Для реальной изоляции нужны отдельный непривилегированный пользователь и системные механизмы Linux — например, namespaces, seccomp и ограничения файловой системы.

## Почему только Linux

Официальный runtime собирается в нативный ELF и использует Linux API. На Windows этот бинарник напрямую не запускается, а код runtime отказывается компилироваться без `__linux__`. Однако текст `.vey` сам по себе остаётся обычным текстовым файлом: нельзя запретить стороннему разработчику написать другой интерпретатор или запускать Linux через виртуализацию/WSL. Ограничение относится к официальному runtime VEYRA, а не является абсолютной защитой исходника.

## Что ещё предстоит

VEYRA пока интерпретатор, а не оптимизирующий компилятор. В план дальнейшего развития можно включить массивы, модули, типовую систему, формальную спецификацию, fuzzing, проверку памяти, отдельный sandbox-процесс и сборку в нативные Linux ELF-файлы. До независимого security review язык не должен быть единственной линией защиты критических систем.
